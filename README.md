# 拱桥智能建造及智能监测综合实验平台 · 数字孪生监测与展示系统 Demo

对应《详细设计和建设方案》**第 6 章 智能化监测分析与展示平台**的可交互演示原型。

> **在线访问（已发布到 GitHub Pages，任何人可打开）**
> <https://lssxiaoxiaosu.github.io/arch-bridge-twin-demo/>
> 仓库：<https://github.com/lssxiaoxiaosu/arch-bridge-twin-demo>（public）
> 首次打开需下载约 15 MB 的 BIM 模型并解析约 5073 万面片，请等加载层走完。
> 同一仓库名重复发布会更新内容、**链接不变**。注意：该仓库为公开仓库，模型与截图均公开可见。

- 三维引擎：Three.js r160（本地 `libs/`，离线可用）
- 图表：Apache ECharts（本地 `libs/echarts.min.js`）
- 模型：平南三桥 BIM（`model/pingnan_bridge.glb`，glTF 2.0 + Draco 压缩）

## 模型规模与性能（请先读这一段）

GLB 内部为 **1439 个几何体**，但场景图存在节点实例化，加载后共 **5173 个构件实例、约 5073 万面片** —— 这是常规桌面 GPU 也能跑但需要取舍的量级（若按方案中的缩尺试验模型建模，面片量通常只有几十万）。因此侧栏提供**显示精度**三档，按"面片预算"保留贡献最大的构件：

| 档位 | 预算 | 说明 |
| --- | --- | --- |
| 精细 | 全部 5073 万面片 | 用于局部查看、截图出图 |
| 标准（默认） | 约 1200 万面片 | 兼顾观感与帧率 |
| 流畅 | 约 200 万面片 | 对齐采购需求「面片 ≤200 万时帧率 ≥30 fps」的验证口径，用于投影与低配设备 |

状态栏与场景右上角实时显示 **fps / 可见面片数 / 可见构件数**，可直接用于性能演示。建议使用独立显卡；集显请切到「流畅」。

## 运行

双击 **`start-demo.bat`**（需要 Python），或在本目录执行：

```
py -m http.server 8099
```

浏览器访问 <http://localhost:8099/>。

> 必须通过 HTTP 访问。直接双击 `index.html` 会因浏览器安全策略（file:// 下的 ES Module / fetch 限制）无法加载模型。

## 数据说明（重要）

本 Demo **无后端**，全部实时与历史数据由 `js/data.js` 中的可复现仿真引擎生成：

- 测点编码、分区、阈值口径与方案第 5 章、附录 D 一致；
- 数值为物理趋势 + 噪声的仿真结果，**不代表任何真实采集数据**；
- 界面固定显示「演示数据」标识，状态栏亦声明数据来源。

正式版按方案第 6 章的技术路线替换为：MQTT(EMQX) + 时序数据库 + 数据服务 + UE5 像素流渲染。

## 深链与自动化钩子

| 参数 | 作用 |
| --- | --- |
| `?view=twin\|dash\|history\|alarm\|hoist\|devices\|system` | 直接进入指定视图 |
| `?prec=high\|standard\|smooth` | 指定显示精度 |
| `?auto=1` | 模型就绪后自动隐藏加载层并暂停渲染（用于截图与投影演示） |
| `?auto=1&freeze=1` | 再进一步冻结渲染循环，便于无头浏览器/自动化取图 |

页面还暴露 `window.__demo`（`engine` / `charts` / `showView` / `twin()` / `hoist()`），便于二次开发与自动化测试。
